# 微信小游戏发布助手（审查改造版）

> 这是独立整理的安全工作流，不是上游代码的直接镜像。上游来源与版本见 README.md。首次使用先识别工程类型，不能把设计稿当作已存在的 Cocos 项目。

## 适用范围与输入

1. 取得待发布**实际工程路径/仓库**、构建引擎及准确版本、目标微信小游戏 AppID（只需在本地配置）、现有构建方式和目标（本地试玩／体验版／开发版上传／提审）。
2. 核对用户有权使用项目代码、图像、音乐、字体、插件及第三方 SDK；记录未解决的授权项。
3. 先检查 Git 工作区状态、现有 CI、引擎版本和已有发布包；保留原有改动，不升级引擎，不覆盖配置。
4. 没有项目时，输出从设计稿到工程原型所缺的事项，不虚构构建、测试或上传结果。

## 必须遵守的边界

- 不删除项目原有公司名、个人署名、版权声明、许可信息或网络接口来“降低相似度”。仅删除已确认无业务用途且经授权的敏感内容，先给出影响和回滚方式。
- 不通过逻辑打乱、无意义函数命名、废代码注入或故意降低可读性来制造“原创性”。原创性通过资产授权、独立玩法、规范代码和真实测试证明。
- 不默认安装依赖、运行陌生第三方脚本、混淆构建产物、改变远程域名、修改 AppID 或触发发布；风险操作前说明影响并获得针对该动作的确认。
- 不读取、打印、提交或保存微信上传密钥、账号密码、Cookie、短信验证码。上传私钥应只保存在用户本机受限目录或合适的 CI Secret。
- 所有上传、提审、正式发布必须分别取得明确确认；任何一次确认不能替代下一阶段确认。
- 仅将已有工具和本地能够验证的成果标记为“完成”，开发者工具测试不能冒充真机测试。
- 技术栈不是 Cocos 时，不执行 Cocos 扩展；先确认可用构建链或提出适配方案。

## 工作流

### 0. 工程和版本预检
- 检查入口、游戏配置、构建脚本、SDK、引擎版本、依赖锁文件、资源许可证、Git 状态、目标平台及设备。
- 记录原始启动/构建命令、可复现的截图、日志和测试清单。生成变更分支，避免直接覆盖游戏源码。
- 若环境缺失，从 Cocos/微信官方渠道获取工具；软件安装与账号登录由用户确认/操作。

### 1. 作品与依赖审计
- 清点素材来源、授权和署名；核查 HTTP 请求、统计、广告、分享、个人信息处理、隐私/用户数据以及第三方 SDK。
- 标记阻断项和优化项，保留有合法用途的联网与元数据。对风险逐项给出修复，不做无差别删除。
- 验证核心业务：存档、撤销、组合、场景切换、触控、离线/弱网、切后台恢复。

### 2. 小游戏适配与构建
- 按确切引擎版本使用官方导出器构建微信小游戏，并核对 `game.json`、`project.config.json`、实际 AppID、分包及启动入口。
- 优先做合法资源优化：图集、压缩、共享材质、剔除未引用资源、资源按需加载、分包/远程资源规划；不得把动态脚本违规放到远端。
- 读取**发布当日**微信官方后台/文档的代码包限额，实际测量主包和全部分包大小，明确统计口径。Cocos 文档中常见的 4MB 主包/30MB 总包只是参考，不替代当日后台限制。
- 构建记录应包含版本号、引擎版本、入口、输出目录、Git SHA、各包大小、资源占比和告警。

### 3. 可选代码保护
- 仅当用户主动要求保护商业代码，且已审核第三方许可/依赖风险时才考虑构建后混淆。
- 优先使用引擎官方压缩/发布选项；不修改源码中的业务函数以追求混淆效果。
- 如采用混淆，备份构建前后结果，保留排除名单，比较包体、启动性能和异常率。任何回归失败都关闭混淆并阻止上传。

### 4. UI、平台能力与真机
- 检查首屏、启动速度、触控可达性、全面屏/刘海屏安全区域、低端 Android 设备帧率及内存。
- 游戏圈、分享、广告等为独立可选能力；依当前官方 API 和实际账号权限接入，不能为了“完成 Skill”强行加按钮。
- 真机验证启动、场景切换、存档恢复、网络中断、切后台、长时操作、字体和布局；记录设备型号、系统、微信版本和结果。

### 5. 发布资料与逐级确认
- 准备候选名称、图标、简介、截图、版本说明和版权凭证；不得声称名称可用或审核必通过。
- 上传前展示 AppID 后四位（不显示密钥）、版本、分支/提交、包体、测试通过/未通过项与已知风险。
- 获得“确认上传开发版本”后才可执行上传，并核对微信后台是否出现对应版本。
- 提交审核、发布上线属于两个新的授权点；分别确认，未获得确认则停止在开发版本阶段。

## 两款游戏的专用检查点
详细见 [references/two-games.md](references/two-games.md)：
- **掌心乡野**：房体与附着件依赖、屋面分区、遮挡选择、分层显示、场景批次、3D/2.5D 渲染与资源预算。
- **拓印小铺**：印章图层、裁切、组合章数据、纹理叠印、撤销栈、作品持久化、缩略图与导出内存。
- 两款都必须有无付费/广告强制门槛的基本创作能力，核心操作必须在真实手机上验证。

每次运行记录：工程与引擎版本、输入与权限、原始基线、改动文件、资源版权状况、包体统计、兼容测试、真机结果、已知问题、是否取得上传授权、上传结果/未上传原因。**不应仅凭这份 SKILL.md 宣称已搭建自动发布系统。**
